# คู่มือทดสอบด้วยมือกับกลุ่ม LINE จริง

ทำตามลำดับ ถ้าข้อไหนไม่ผ่านให้หยุดและแจ้ง อย่าข้ามไปข้อถัดไป

## เตรียมก่อนเริ่ม

| ต้องมี | ใส่ที่ไหน |
|---|---|
| Neon pooled connection string | `DATABASE_URL` |
| Neon direct connection string | `DATABASE_URL_UNPOOLED` (ใช้ตอน migrate เท่านั้น) |
| LINE Login channel ID + secret | `LINE_LOGIN_CHANNEL_ID` / `_SECRET` |
| Messaging channel secret + access token | `LINE_MESSAGING_CHANNEL_SECRET` / `_ACCESS_TOKEN` |
| LIFF ID | `NEXT_PUBLIC_LIFF_ID` (ค่าเดียวที่เป็น public ได้) |
| โดเมนจริง | `APP_BASE_URL` |

ตั้ง Webhook URL ในคอนโซล LINE เป็น `https://<โดเมน>/api/webhooks/line`
**ต้องเป็นโดเมนถาวร ไม่ใช่ URL พรีวิวที่เปลี่ยนทุก deploy** เพราะเปลี่ยนทีต้องมากด verify ใหม่ทุกครั้ง

รัน migration ครั้งเดียว: `npx drizzle-kit migrate`

---

## 1. บอทเข้ากลุ่ม

1. เชิญ OA เข้ากลุ่มทดสอบ
2. **ถ้ากลุ่มมี OA อื่นอยู่แล้ว บอทจะเข้าไม่ได้** นี่คือข้อจำกัดของ LINE ไม่ใช่บั๊ก
   ให้ทดสอบเส้นทางสำรองแทน: ทักหาบอทใน DM แล้วดูว่ายังสร้างงานได้
3. ผ่านเมื่อ: บอทอยู่ในกลุ่ม หรือเส้นทาง DM ทำงาน

## 2. ข้อความติด @ทันงาน กลายเป็นดราฟต์

1. พิมพ์ในกลุ่ม: `@ทันงาน @<ชื่อสมาชิก> ส่งใบเสนอราคาให้ ABC ภายในวันนี้`
2. ผ่านเมื่อ: บอท**ตอบกลับในกลุ่ม** พร้อมชื่องานและกำหนดส่งที่อ่านได้
3. ตรวจว่าเป็น reply ไม่ใช่ push: `GET /api/usage` ตัวเลข `used` **ต้องไม่เพิ่ม**
   (reply ไม่นับโควตา ถ้าตัวเลขขยับแปลว่าส่งผิดวิธีและจะเปลืองเงิน)

## 3. ไม่ติด @ ต้องไม่เกิดอะไรขึ้น

1. พิมพ์ข้อความธรรมดาในกลุ่มโดยไม่ติด `@ทันงาน`
2. ผ่านเมื่อ: **ไม่มี**ดราฟต์เข้ากล่อง และบอทเงียบ
   นี่คือข้อที่ทำให้คำโฆษณา "บอทไม่ได้อ่านทุกข้อความ" เป็นจริง

## 4. ยืนยันครั้งเดียวได้งานหนึ่งงาน

1. เปิดแอปในกลุ่ม → กล่องข้อความ → กดยืนยันดราฟต์
2. ผ่านเมื่อ: ได้งาน 1 งาน มีผู้รับผิดชอบและกำหนดส่งตามที่ยืนยัน
3. กดยืนยันซ้ำอีกครั้ง → ต้องได้ **409** ไม่ใช่งานที่สอง

## 5. เตือนถึงผู้รับงานทางแชทส่วนตัว ตรงเวลาไทย

1. สร้างงานที่กำหนดส่งอีกประมาณ 1 ชั่วโมง
2. ผ่านเมื่อ: ผู้รับงานได้ **DM ส่วนตัว** ไม่ใช่ข้อความในกลุ่ม
3. ตรวจเวลาเป็น Asia/Bangkok
4. `GET /api/usage` → `used` เพิ่มขึ้น **1 ต่อผู้รับหนึ่งคน**
   (ถ้าเพิ่มเท่าจำนวนคนในกลุ่ม แปลว่าส่งเข้ากลุ่มผิด)

> ตัวจับเวลาอัตโนมัติยังไม่ได้ทำตามที่สั่ง ตอนนี้ต้องยิงเองเพื่อทดสอบ

## 6. สมาชิกที่ยังไม่ได้เพิ่มบอทเป็นเพื่อน

1. มอบงานให้คนที่ยังไม่ได้แอดบอท
2. ผ่านเมื่อ: UI ขึ้น**คำเตือนว่าคนนี้รับ DM ไม่ได้** ไม่ใช่เงียบหาย
3. `canReceiveDirectMessages` ของคนนั้นต้องเป็น `false`

## 7. ห้าปุ่มสถานะบนมือถือ

ทำทีละอันในมือถือจริง: รับงาน → ขอข้อมูล → ติดปัญหา → ส่งต่อ → ส่งงาน

ผ่านเมื่อ: ทุกปุ่มกดครั้งเดียวติด, สถานะเปลี่ยนจริง, และ `task_event` มีบันทึกครบทุกครั้ง
`ส่งงาน` ต้องบังคับให้ใส่ลิงก์หลักฐานก่อน

## 8. เว็บฮุคซ้ำต้องไม่สร้างงานซ้ำ

1. ใน LINE console กด **Verify** ซ้ำ หรือส่งข้อความเดิมซ้ำโดย LINE retry
2. ผ่านเมื่อ: จำนวนงานไม่เพิ่ม
3. ตรวจในฐานข้อมูล: `select count(*) from line_event where webhook_event_id = '<id>'` ต้องได้ 1

## 9. ข้อมูลต้องไม่ข้ามพื้นที่งาน

1. ให้บัญชี B ที่ไม่ได้อยู่ในพื้นที่งานของ A เรียก
   `GET /api/tasks?workspaceId=<ของ A>`
2. ผ่านเมื่อ: ได้ **404** และไม่มีข้อมูลของ A หลุดมาเลย

## 10. ลบข้อความใน LINE แล้วข้อความดิบต้องหาย

1. ส่งข้อความติด `@ทันงาน` แล้วกดยกเลิกการส่งใน LINE
2. ผ่านเมื่อ: `raw_message` ของรายการนั้นเป็น `NULL`

## 11. โควตาตรงกับที่ LINE รายงาน

1. เทียบ `GET /api/usage` กับตัวเลขใน LINE Official Account Manager
2. ผ่านเมื่อ: ตรงกัน **โดยนับตามจำนวนผู้รับ ไม่ใช่จำนวนครั้งที่เรียก API**

> เตือนความจำเรื่องต้นทุน: ทีม 10 คน วันละ 2 เตือน 22 วันทำงาน = 440 ข้อความ
> ต่อเดือนต่อทีมเดียว แต่แผนฟรีให้ 300 ต่อเดือน — ทีมเดียวก็เกินแล้ว
> จึงต้องใช้สรุปรวมรายวันเป็นค่าเริ่มต้น ไม่ใช่เตือนรายคนทุกครั้ง

## 12. มือถือจริงใน LINE WebView

เปิดจาก LINE บนแอนดรอยด์รุ่นกลาง ใช้คีย์บอร์ดไทย

ผ่านเมื่อ: เลือกทีมได้ สร้างงานได้ เลือกวันได้ ส่งงานได้ และ
**ไม่มีกล่องไหนหลุดขอบจอตอนคีย์บอร์ดเด้งขึ้นมา**
